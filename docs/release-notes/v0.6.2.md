## 重點

- **座席流程**：座席可以在註冊後、每通結束後、測試結束前依序撥特殊碼，例如登入 `*94{agent}*{pwd}`、就緒 `*96`、未就緒 `*97`、登出 `*95`。GUI 有可拖曳排序的設定彈窗，測試中也能用按鈕手動撥碼。
- **民眾端發話節奏**：新增「批次」模式（每 M 秒一次發出 N 通）與「補話延遲」（線路釋放後等 N 秒才補）。
- **SIPX 雙端壓測的預設值調整**：響鈴 1–2 秒再接、註冊間隔 1000 ms、「通話後重新註冊」標示 SIPX 勿開。

## 新功能

### 座席流程（撥特殊碼登入 / 就緒 / 登出）

- GUI 座席區塊「座席流程 → 設定…」：三個時間點（測試開始 / 每通結束後 / 測試結束），每段由「撥碼」與「等待」步驟組成，按住 ⠿ 拖曳調整順序，也能拖到其他時間點。
- 變數：`{agent}` = 分機末幾碼（預設 4，例如 0000021113333001 → 3001）、`{pwd}` = 座席密碼；彈窗會預覽第一個分機實際撥出的號碼。
- 常用碼（可修改）：登入 `*94{agent}*{pwd}`、就緒 `*96`、未就緒 `*97`、登出 `*95`。
- 一鍵套用：
  - 「SIPX 預設」（掛線後自動就緒）：開始時登入 → 等待 1 秒 → 就緒；結束時未就緒 → 等待 1 秒 → 登出；每通結束後不撥碼。
  - 「非自動就緒」：同上，再加每通結束後等待 3 秒 → 就緒。
- 撥碼的判定：交換機回 200 OK，或回 183 播提示音算成功（座席保持「撥通 / 提示音後保持」秒數後掛斷，預設 1 秒；交換機以 487 結束也算成功）；要求認證（401 / 407）時用座席帳密重送；其他錯誤回應（log 附 `Reason`，例如 `CTIError2140`）或 15 秒沒有回應算失敗。
- 測試進行中，側欄「座席狀態（手動撥碼）」的登入 / 就緒 / 未就緒 / 登出按鈕，讓所有已註冊的座席依註冊間隔逐一撥出。
- 結果寫在 SIP log（`[撥碼]` 開頭的事件）、即時 log 與最終報告（每個撥碼的成功 / 失敗與回應碼）。
- CLI：用「座席流程」的「匯出」存成 JSON，加上 `--agent-flow sipress_flow.json`。

### 批次發話與補話延遲（民眾端）

- CPS 模式新增「批次 Batch」（CLI `--cps-batch N/M`）：每 M 秒一次發出 N 通，例如 `3/20`。發出時併發已滿，只補空出的線路，這一批剩下的略過、不累積。
- 「補話延遲」（CLI `--refill-delay 秒`）：線路釋放後等幾秒才補新的通話，所有 CPS 模式都適用。雙端壓測時可避免新來電剛好在座席掛線的瞬間進線。

## 調整

- GUI 座席預設：響鈴 1–2 秒才接（0 秒時 100 / 180 / 200 幾乎同時送出，SIPX 的 CTI 可能漏掉「接聽」事件）；註冊間隔 1000 ms，欄位下方顯示預估註冊完成時間。CLI 預設不變。
- 「通話後重新註冊」標示「SIPX 勿開」：CTI 會把掛線後的註冊當成座席重新登入，座席之後不再被派話。

## SIPX 雙端壓測注意事項

實測 SIPX（3 座席、3 併發）時查到的現象，供設定與排查參考：

- 客服群組設定「非自動空閒」時，座席掛線後立即可派；CTI 會在座席掛線的同一秒派下一通，此時 SIPX 可能回 506，CTI 隨即把座席設為未就緒（cti.log `astate=1 aestate=21`），之後不再派話。改為「自動空閒」並設話後處理秒數可避開。
- 掛線後馬上撥特殊碼會佔住分機，讓上述派話失敗更常發生；SIPX 自動就緒時，每通結束後不要撥就緒。
- 測試前請確認沒有之前測試留下、仍在 CTI 登入狀態的座席（CTI 會先派給它們、每次失敗 506）；座席流程的結束步驟會撥登出避免留下。

## 升級注意事項

- GUI 會保留已存的設定，新的預設值（響鈴 1–2 秒、註冊間隔 1000 ms）只套用在沒存過的欄位；從舊版升級請手動確認。
- 設定檔新增 `agent_flow`、`refill_delay_secs`，CPS 模式新增 `{"type":"batch","count":N,"every_secs":M}`；舊設定檔沒有這些欄位時使用預設值。
- 即時快照新增 `agent_dials_ok` / `agent_dials_failed`；最終報告有座席流程時多 `agent_dials` 欄位。只新增欄位，沒有移除。
