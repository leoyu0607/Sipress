## 新功能

- **民眾端通話流程（測試按鍵 IVR 與智能語音 IVR）**：民眾端設定新增「通話流程 → 設定…」，每通接通後依序執行這些步驟（#39）：
  - **等待**：送靜音 N 秒，例如先聽完前 10 秒招呼語再播音檔。
  - **按鍵**：例如 `1`、`0912345678#`。按鍵與語音走同一路 RTP 串流（同一個 SSRC、序號連續）。
  - **播放音檔**：播一次；可放多個檔案，每通隨機挑一個。
  - **說話（TTS）**：輸入文字，用 Azure AI Speech 或 Google Cloud TTS 合成台灣華語語音；可放多種說法，每通隨機挑一種。視窗內可直接試聽。
  - **等對方講完**：偵測對方說完話、安靜 N 毫秒後才進行下一步，超過最長等待秒數就直接下一步；適合 AI IVR 回答長短不一的情況。
  - 可勾選「流程跑完就掛斷」。視窗內附「按鍵 IVR」與「語音 IVR」範例。
  - TTS 在按下開始時合成一次並快取在 `tts_cache/`，壓測期間不連線到 TTS 服務；金鑰或區域錯誤會在開始時直接顯示。文字會送到所選的雲端服務合成。
  - API 金鑰可填在 GUI，或設環境變數 `SIPRESS_TTS_KEY`；金鑰不會寫進結果檔與匯出的流程檔。
  - CLI：用 GUI 的「匯出」存成流程檔，執行時加 `--rtp --caller-flow sipress_caller_flow.json`。
  - 沒有設定流程時，原本的「播放音檔」與「DTMF 序列」行為不變。

## 修正

- **RTP 序號回繞不再造成假掉包與 MOS 1**：對方的 RTP 序號從 65535 回到 0 之後、最高序號還沒追過該通的第一個序號之前，應收封包數會多算 65,536，使該通電話、10 秒時段與整場的掉包率異常偏高，MOS 掉到 1。長通話（約 22 分鐘以上）或對方起始序號接近 65535 時就會發生。現在改用正確的延伸序號計算（#40）。
  - 以 v0.7.4 回報的結果檔重建場景比對：座席端整體掉包率 51.80% → 0%、民眾端 32.15% → 0.01%（剩下的是一通完全沒收到 RTP 的電話）。
  - 先前受影響的結果檔無法事後更正，請用新版重新測試。
