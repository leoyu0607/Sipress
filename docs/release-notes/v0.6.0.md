## 重點

- **TCP 傳輸**：民眾端、座席端與 GUI「測試註冊」都可以選 TCP，每個民眾端 / 座席帳號各用一條長連線。
- **長時間耐久測試的分時段統計**：每 N 分鐘一段的 CPS、ASR、PDD、MOS、失敗碼，HTML 報告畫成趨勢圖，CLI 可輸出 CSV，看得出第幾小時開始變差。
- **codec 協商**：依 SDP offer / answer 決定 PCMA / PCMU，送出的 RTP 編碼與宣告一致；對方沒有 G.711 時座席回 488。
- **撥號認證**：SIPX 對 INVITE 回 401 / 407 時，民眾端帶 Digest 認證重送。
- **CLI 補齊 GUI 的設定**：CPS 漸增 / 階梯 / 尖峰、codec、DTMF；GUI 的 CLI 預覽可完整重現設定。
- **大量帳號的座席端修正**：5000 個帳號的記憶體由約 5 GB 降到約 40 MB；REGISTER 遺失時會重傳。

## 新功能

### TCP 傳輸

- GUI 的「傳輸協定」或 CLI `--transport tcp`。訊息依 `Content-Length` 分框，TCP 時不做 SIP 層重傳。
- Via、Contact 都標明 TCP；座席的 REGISTER Contact 帶 `;transport=tcp`，伺服器才會用同一條連線把來電送給座席。
- 限制：伺服器打給座席的請求必須走座席註冊的那條連線（一般 proxy 的做法）；RTP 仍為 UDP；不支援 TLS。

### 分時段統計

- 每 `--interval`（預設 5 分鐘，例如 `30s`、`5m`、`1h`；`0` = 不分段）結算一段：發起 / 接通 / 完成 / 失敗 / 逾時、CPS、ASR、PDD P50 / P95、MOS、失敗碼。各段加總等於最終報告。
- HTML 報告（CLI `--html` 與 GUI 匯出）兩段以上時顯示 CPS / ASR / PDD / MOS 趨勢圖與每段明細表。
- CLI 表格輸出後附分段表；`--timeline-csv <檔案>` 每段一列；JSON 報告多了 `timeline` 欄位。

```bash
./sipress -s 10.0.0.1:5060 --to 168168999 -c 200 --cps 20 -d 28800 --interval 10m --html --timeline-csv soak.csv
```

### codec 協商

- 民眾端 offer 把偏好的 codec 放第一個，依 200 OK 的 answer 決定實際送出的 codec。
- 座席端依 INVITE 的 offer 選 codec（有偏好的就用偏好的），answer 只宣告選中的那一個；offer 完全沒有 PCMA / PCMU 時，在響鈴前回 `488 Not Acceptable Here`。
- 選到 PCMU 時，音檔在送出前轉成 μ-law，封包的 payload type 與內容一致。
- 音檔在測試開始前先載入；格式不支援時直接報錯，不會整場改送靜音。GUI 選檔視窗只列實際支援的格式。

### 撥號認證（INVITE 401 / 407）

- GUI 民眾端「撥號認證帳號 / 密碼」，CLI `--auth-user` / `--auth-pass`。帳號未填時使用該通的主叫號碼。
- 以同一個 Call-ID、CSeq + 1、新 branch 帶 `Authorization` / `Proxy-Authorization` 重送一次；帶認證仍被拒才算失敗。
- GUI 的 CLI 預覽以 `"<密碼>"` 代替真實密碼。

### CLI 新參數

| 參數 | 說明 |
|---|---|
| `--transport tcp` | TCP 傳輸 |
| `--cps-ramp 5-50` | CPS 漸增（需 `-d` > 0） |
| `--cps-steps 10:30,50:60` | CPS 階梯（每階 `CPS:秒`） |
| `--cps-spike 10,100,50,10` | CPS 尖峰（基準, 尖峰, 開始 %, 秒數） |
| `--codec pcmu` | 偏好的 codec（預設 pcma） |
| `--dtmf 1,w2000,#` | 接通後送出的 DTMF（需 `--rtp`） |
| `--auth-user` / `--auth-pass` | 撥號認證 |
| `--interval 5m` / `--timeline-csv` | 分時段統計 |
| `--reregister-after-call` | 座席每通結束後立即重新註冊（舊版行為，見升級注意事項） |

### 其他

- 支援 IPv6 位址（SIP URI 加中括號、SDP 用 `IN IP6`）。
- 效能基準 `core/examples/load_bench.rs` 與結果 `docs/performance.md`：沒有 RTP 時 5000 通並發只用約 1–16% 單核；RTP 每路每秒 50 個封包，5000 路約需 3 核，建議每核心約 1500–2000 路。

## 修正

- **即時指標**：
  - 即時 CPS 改由引擎每秒計算，不再出現 0 與兩倍交替。
  - 即時 ASR / ERR% 只看已有結果的通話，不會被還在響鈴的通話拉低。
  - PDD 測試中與結束後都顯示 P50，結束時數字不再跳動。
  - 時間到後的收尾期間持續更新，直到引擎結束；結束後「並發」顯示 0。
- **座席端大量帳號**：每個帳號原本各複製一份完整帳號清單，記憶體與啟動時間隨帳號數平方成長（5000 個帳號約 5 GB）；閒置的 UDP socket 各占 64 KB。
- **座席 REGISTER 遺失時不重傳**：大量帳號同時註冊時伺服器可能漏收，該帳號要等約 2 分鐘的刷新才上線。現在依 RFC 3261 重傳（0.5 秒起加倍、最長 4 秒、32 秒放棄）。
- **`--from-seq`**：ACK / CANCEL / BYE 的 From 與該通 INVITE 不一致。
- **DTMF 格式**：`123#` 這種不加逗號的寫法原本只送出第一個按鍵；現在 GUI 與 CLI 都會提示格式錯誤（正確寫法 `1,2,3,#`）。
- **CLI `--transport tls`** 原本會被默默當成 UDP，現在直接報錯。
- SIP User-Agent 與 HTML 報告頁尾顯示實際版本號（原本固定為 0.1）。
- GUI：撥號認證欄位版面擠壓、側欄參數標籤斷行。

## 升級注意事項

- **座席端預設不再每通都重新註冊**：v0.5.0 每通結束後都會送一次 REGISTER，高話務時會對交換機多送大量 REGISTER。現在只在 Expires 到期前刷新；交換機確實要求通話後重新註冊才會繼續派話時，請開啟 GUI「通話後重新註冊」或 CLI `--reregister-after-call`。
- **即時 ASR 的計算方式**：測試中的 ASR 會比 v0.5.0 高（分母不含還在響鈴的通話）；最終報告的 ASR 不變。
- **DTMF 必須用逗號分隔**：已存的 GUI 設定若是 `123#` 這類寫法，開始測試時會提示錯誤，改成 `1,2,3,#` 即可。
- **JSON 報告**多了 `timeline` 欄位；即時快照多了 `cps`、`pdd_p50_ms`。只新增欄位，沒有移除。
- **SIP log**：座席端回應訊息的對端標示由 `server` 改為實際的 server 位址。
